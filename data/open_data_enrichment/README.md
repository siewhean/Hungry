# Open-data venue enrichment

Generated by `scripts/enrich_from_open_data.py`. It fills gaps in `data/catalog_load/venues.csv` (opening hours, website, phone, cuisine tags, dietary tags) from open-licensed public data. It also runs informational checks on hygiene grades and geocodes. Nothing is written to the database until you apply the SQL.

## Sources and licences

| Source | What it provides | Licence |
| --- | --- | --- |
| OpenStreetMap (Overpass API) | opening_hours, website, phone, cuisine, diet:halal/vegetarian/vegan | ODbL 1.0 |
| data.gov.sg: "List of NEA Licensed Eating Establishments with Grades…" (found through the collections API; fallback id `d_227473e811b09731e64725f140b77697`) | licence-number matching, informational grade count | Singapore Open Data Licence v1.0 |
| Overture Maps Places (latest release, Singapore bbox only, read with DuckDB) | websites, phones, category to cuisine | CDLA-Permissive-2.0 (some upstream records carry their own licence, which is kept in `*_licence`) |
| Foursquare OS Places | websites, phones, category to cuisine | Apache-2.0 |
| OneMap search | postal-code geocode check (`geocode_checks.csv`) | Singapore Open Data Licence v1.0 |

No Google, Grab, Foodpanda, TripAdvisor or restaurant-site scraping is used. Website values that point at socials, delivery apps, review sites or short links are dropped.

### Attribution (required)

- **"© OpenStreetMap contributors, ODbL"**, with a link to https://www.openstreetmap.org/copyright wherever OSM-derived hours, phones, websites, cuisine or dietary tags are shown.
- "Contains information from data.gov.sg, made available under the Singapore Open Data Licence v1.0."
- "Contains data from Overture Maps Foundation (CDLA-Permissive-2.0)."
- "Contains data from Foursquare OS Places (Apache-2.0)", only if that source was enabled.

### Share-alike caveat (ODbL)

ODbL is share-alike. If venue rows that include OSM-derived values are published as a database, or a derivative database is distributed, that derivative must also be offered under ODbL. Showing the values in the app is a "produced work", which only needs attribution. Exposing the venue table through a public API or as a data export, however, could count as a derivative database. Every filled field records its source in `<field>_source` / `<field>_licence` (`operating_hours_*`, `website_url_*`, `contact_phone_*`, `cuisine_*`, `dietary_*`). Use these to tell OSM-derived values apart, or to drop them. The `venues` table has no provenance column yet, so provenance lives only in the CSV. Persisting it would need a migration.

### Hygiene grade

`hygiene_grade` is never updated. The column is `NOT NULL CHECK (A–D)` and the app does not show it. The only published grade list is NEA's list, which predates the 2019 SFA transfer, so its grades are historical. `summary.json` reports how many venues have a published grade and how many sit on the workbook or default grade. The SFA "Eating Establishments" and "Certificate Grading" collections are listed on data.gov.sg, but they have no child datasets.

## Matching

1. SFA licence number (exact; data.gov.sg)
2. postal code + normalised name similarity ≥ `--name-threshold` (0.85)
3. distance < `--max-distance-m` (40 m) + name similarity ≥ `--near-threshold` (0.75)

Names are normalised before comparison: lowercased, accents removed, legal suffixes such as "Pte Ltd" and bracketed text stripped. Similarity is `difflib`, taking the better of the plain ratio and the token-sorted ratio. Each row records `match_method` and `confidence`. If several sources offer the same field, `--priority` decides (default `datagov,osm,overture,foursquare`). Dietary tags are unioned.

Only fill-ins are emitted: a field the venue already has is skipped unless `--overwrite` is set. OSM `opening_hours` is converted to the app's text format (`Mon-Fri 11:00-22:00; Sat 10:00-23:00`), with off days omitted, because `src/utils/stallStatus.ts` treats the word "closed" as closed now. Rules with month, week or comment syntax are not converted; the raw value stays in `osm_opening_hours`.

## Run

```bash
pip install --user duckdb   # only needed for Overture/Foursquare
python3 scripts/enrich_from_open_data.py --sources osm,datagov,overture,foursquare,onemap \
  --venues data/catalog_load/venues.csv --out data/open_data_enrichment [--overwrite] [--limit N] [--offline]
```

Responses are cached in `data/open_data_cache/`, which is gitignored. `--offline` uses the cache only. Requests are rate-limited and send a `Hungry-open-data-enrichment` User-Agent; failed requests are retried with 2/4/8/16 s backoff.

**Foursquare is gated.** To enable it, sign in to Hugging Face, accept the terms at https://huggingface.co/datasets/foursquare/fsq-os-places, create a read token, and `export HF_TOKEN=...` before running. Without a token the source is skipped and the skip is logged in `summary.json`. A valid token whose account has not been granted access gets HTTP 403. That is also logged, and the source is skipped. Access must be requested on the dataset page.

**OneMap** search works without a token, so it is used for postal-code geocode checks only. Planning-area lookup needs a token and is skipped.

## Apply

Requires migration `20261018130000_venue_contact_links.sql` (website_url, contact_phone, menu_url). The script aborts if a column is missing. It runs as a single transaction and prints before/after fill counts:

```bash
psql "$DB_URL" -v ON_ERROR_STOP=1 -v commit=0 -f data/open_data_enrichment/apply_enrichment.sql  # dry run (rollback)
psql "$DB_URL" -v ON_ERROR_STOP=1 -v commit=1 -f data/open_data_enrichment/apply_enrichment.sql  # apply
```

## Files

- `venue_enrichment.csv`: one row per venue with fill-in values and per-field provenance.
- `unmatched_osm.csv`: OSM places with no venue match (candidate new venues; ODbL).
- `geocode_checks.csv`: OneMap postal geocode against catalog coordinates (flag over 250 m).
- `summary.json`: counts per source and field, match methods, licences, run log.
- `apply_enrichment.sql`: the psql apply script.
