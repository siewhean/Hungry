Hungry v2 / 02 Discover & Search

Three discover directions — from map-first to intent-first.

The current HomeMapScreen has no search bar, a placeholder map, and a disconnected building list. All three variants unify search, discovery, and map into a single coherent surface. The dish section is elevated as first-class content in all variants — not buried in a separate tab. Stall vs user differentiation uses icon + ring cues, not pill labels.

Dishes section in Discover Stall vs User visual cues Decide for Me prominent No redundant pill buttons Map entry from search context

Current Implementation Audit

What's wrong with HomeMapScreen.tsx + Search

Issue · Lines 99–156

Map is a placeholder rectangle with absolute pins

Zero spatial context. Users cannot infer distance, direction, or density from fixed percentage positions. All 3 variants replace this with a proper styled map surface with roads, blocks, and accurate pins.

Issue · Line 107

"Dish pick" is a plain Button — not prominent enough

The "Decide for Me" feature is one of the most valuable differentiators. It should be a visually distinct card, not a small button tucked in a header row. All variants make it a full-width branded card.

Missing feature

No search bar on the Discover landing

The Discover tab is the tab users land on after onboarding. It should have a search entry point immediately visible without switching to the Search tab.

Missing feature

Dishes not surfaced on Discover — only buildings

Users can't see what food is available until they drill into a building. Variant A and C surface trending dishes directly on the Discover page — dish-first, not venue-first.

Variant A — Recommended

Unified Discovery

Recommended

Search + intent chips + tap targets + dish scroll — all on one surface

Keeps the map accessible via a dedicated button, but the landing state is about food discovery — not navigation. Intent chips are contextual (not persistent pills). The two large tap targets "Stalls" and "Dishes" are card-sized, not pill-sized.

  • Sticky search bar + mic at top
  • Intent chips scroll horizontally — situational, not permanent
  • 2 large tap targets: Stalls & Dishes (card-sized, not pills)
  • Decide for Me card — gradient orange, prominent
  • Trending dishes horizontal scroll below targets
  • Stall list: orange ring + fork icon vs user grey ring
  • Map enters via icon button — not hidden, not primary

Variant B

Map-First Discovery

Spatial discovery

Full-screen map as landing — pull-up sheet reveals food content

For users who think spatially — tourists, office workers exploring the area. The map is the primary surface. A draggable bottom sheet reveals nearby stalls and dishes without leaving the map context. "Decide for Me" is a floating action button that's dismissible.

  • Full-screen styled map as landing (no blank rectangle)
  • Building pins with type color: orange=hawker, teal=food court, navy=restaurant
  • Pull-up sheet: 3 positions (collapsed / half / full)
  • Search bar embedded in sheet header
  • Decide for Me: floating orange FAB
  • Sheet in full state shows same stall/dish list as Variant A

Variant C

Intent-Based Discovery

AI-first

"What are you craving?" — taste categories lead to filtered results

Directly addresses the problem of decision paralysis. Rather than showing a list of options immediately, it asks the user what kind of food experience they want. The 6 taste tiles are 3D tactile buttons — selecting them filters dishes intelligently. After selection, a results screen with matching dishes appears.

  • Landing: large "What are you craving?" heading
  • 6 taste tiles (3x2): Spicy / Rich / Sweet / Sour / Fresh / Crispy
  • Search bar at top for override
  • Tile selection → results screen: dish cards filtered by taste
  • Country-flag filter: "Popular with 🇰🇷 Koreans" etc.
  • Results cards: dish photo, name, stall, distance, save — no extra pills
