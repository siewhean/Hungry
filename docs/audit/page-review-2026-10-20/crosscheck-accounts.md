## Material challenges and corrections

1. **Reject the original “Change Password has no incoming caller” subclaim.** `EditProfileScreen.tsx:103–105,181–194` explicitly navigates to `AuthStack/ChangePassword`. It is a production user journey through Profile → Edit profile, not merely an eagerly imported unreachable screen. The primary auth report has been corrected by root. The broken validators and failed compiler/service-boundary gates remain valid.
2. **Downgrade original SET-01 from P1 privacy exposure to P2 inert control.** Repository-wide non-test consumer search confirms the switch does nothing, but “Hide reviewed dishes from public feed” does not unambiguously specify whose feed/audience. Resolve product semantics before asserting a public visibility leak; the real Profile visibility control is separately implemented. SET-03 is a distinct, well-supported P1 privacy-state race.
3. **Narrow PROFILE-06:** ordinary navigation that pushes a quiz/password screen does not establish the editor was unmounted. Native-stack routes commonly preserve the underlying component. Actual back/pop/unmount/root reset/restart loses local draft state; no discard/persistent-draft boundary exists. The primary profile report has been corrected by root.
4. **Do not erase existing loading UI.** `ProfileConnectionsScreen.tsx:65,338–343` and `SocialGridScreen.tsx:45,218–224` do have loading indicators. PROFILE-08 remains valid for their failure-to-empty behavior and for other screens' missing load states, but not as a blanket “none of these pages shows loading” claim.
5. **Keep source proof separate from device/privacy deployment proof.** A 40/32/28-point style or absent accessible name is a source gap, not a measured focus/hit-frame failure; optimistic and deferred race consequences require deterministic integration/device closure. The checked-in follow RLS mismatch proves a source contract mismatch, not the deployed policy state.
6. **Correct first-run interpretation:** root's current-source browser smoke encountered Welcome instead of the old test's expected Login. `SplashScreen.tsx` sends unfinished onboarding to `OnboardingStack`. This is a stale expectation, not evidence of a crash or authentication bypass. Root reports a supplemental Welcome → existing-account Sign in check passed; this reviewer did not independently run or inspect that browser session.

## Verification and release limits

Performed read-only `rg`/bounded source/SDK/migration inspection, report-manifest/ID accounting, and source fingerprint comparison. No broad test rerun, provider authentication, writes, emails, build/install, native navigation, destructive deletion or external policy certification was attempted by this reviewer.
