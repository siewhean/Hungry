Adjudication terms: **accepted** means the source mechanism is independently present; **narrowed** qualifies a true concern's trigger, scope, consequence or severity; **rejected** contradicts the inspected source; **unresolved** requires more evidence. Review-only checks cannot establish an error-free application.

## Material challenges

- **RP-01:** a generic “sign out” trigger would be misleading. `SettingsScreen.tsx:278–280` explicitly resets the review draft. The production Profile menu (`ProfileHomeScreen.tsx:643–653`), session expiry and direct subject changes omit that reset. The primary report now makes this distinction. A retained private draft is not proof of a remote leak or a completed publication under another account.
- **RP-03:** pushing an auth route does not itself prove component unmount or draft loss. Native stacks can retain the underlying screen. Actual pop, route reset/unmount or process recreation loses the local production composer state. Keep that concrete trigger rather than treating every navigation as destructive.
- **RP-12:** `openTrustedMessagingShareUrl()` returns `Promise<void>`, not a boolean. Its catch shows an alert and resolves, so the caller can count a share after an unsuccessful open. That helper does not itself propagate the alleged failed-open rejection. `Share.share()` remains a separate uncaught/cancellation-insensitive path. Root was notified to correct this wording.
- **RP-13/18:** missing roles/values and explicit style dimensions can be inspected in source; rendered target geometry, modal focus, clipping, completion time and usability superiority require device/user evidence. The design comparison is a reasoned critique, not a functional or legal violation by itself.
- **RP-14–17:** Quick Review has a global host but no caller; prototype composer is flag-gated; MusicSelection is registered but its current UI callers are prototype-gated. These defects do not establish ordinary production task failures merely because files or route names exist.
