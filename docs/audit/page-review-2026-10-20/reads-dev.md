## Judgment and scope

Reads is not currently a shippable, discoverable reader experience: the feed is unreferenced and its flag is unused. The article route is registered in production, but the only currently live caller found is the development launcher's Article button; therefore article/feed defects below are **latent or development-reachable**, not proof that current production users hit these failures. Developer tooling offers convenient navigation and presets but several controls simulate only their appearance. This weakens QA evidence even when the resulting screen looks correct.

Governing source: `docs/audit/PROFILE_READS_SPEC.md`, read during inspection, requires real read-time metadata, actionable Archive and token-based atmosphere styling. It is a partial April specification and does not define a current full reader or developer-tool design. `tasks/product-context.md:86` describes an excerpt-only food-blog aggregator, but actual navigation has since changed. No approved dedicated Developer Launcher or Design Gallery screen artifact was found. No rendered design-fidelity or native accessibility claim is made. I inspected all four files, shared Screen layout, safeLinking, service provider switching, mock blog data, Supabase article mapping/cache/service methods, blog schema/RLS and route registrations/callers. The code reads preceded completion of the textual design-source review; this was an audit only, with no UI implementation.

## Findings

### RD-01 — P2 — Reads is enabled in name but has no route or entry point

**Class:** confirmed source integration/contract drift. **Evidence:** `src/constants/featureFlags.ts:24` returns `readsEnabled: true`; source-wide non-test search finds no consumer of that flag and no import of `ReadsFeedScreen` beyond its declaration. `src/app/navigation/SwipeableTabNavigator.tsx:45` loads `ReviewFeedScreen`; its registered tabs at lines 325–328 are Home/Discover/Review/Profile. `RootNavigator.tsx:718` registers the article route, not the Reads list. **Trigger/consequence:** a user seeks the documented Reads experience and cannot reach it. **Recommendation/owner:** product + navigation owner decide whether Reads is intentionally deferred; either wire the approved entry and state model or reconcile flag/docs and keep the orphan clearly dormant. Do not reinterpret the Review tab as Reads. **Close:** inventory actual route and entry behavior in the intended release, then test access and Back; no production content feature should be advertised from an unused flag.

### RD-02 — P2 — Empty article cache crashes render instead of showing loading or missing content

**Class:** confirmed source defect; latent/development-reachable today. **Evidence:** `reads/BlogPostWebViewScreen.tsx:17–18` obtains a synchronous list and chooses the requested item or `posts[0]`; lines 32–35 unconditionally access `post.title`, `.excerpt`, `.relatedVenueId`. The `if (!post)` at lines 21–23 protects only the effect. Supabase starts with `cachedBlogPosts=[]` (`supabaseRepository.ts:172`); `listBlogPosts()` at 1126–1128 returns it immediately while `ensureHydrated()` starts work asynchronously at 749–752. **Trigger/consequence:** article route mounts before hydration, or catalog legitimately contains no articles; component throws during render. **Recommendation/owner:** content/mobile engineer await an article service with explicit pending/not-found/error states and no unconditional dereference. **Close:** mount against delayed empty/nonempty responses, permanent empty, failure and removed ID; confirm recovery with Back/Retry without an error-boundary-only dead end. This is not a native crash reproduction or a currently discoverable production flow.

### RD-03 — P2 — Unknown article IDs silently open a different article

**Class:** confirmed source identity defect, same reachability limit as RD-02. **Evidence:** `reads/BlogPostWebViewScreen.tsx:18` uses `?? posts[0]` for a failed ID lookup. **Trigger/consequence:** stale/deleted/wrong ID with a nonempty list displays and automatically opens the first unrelated article, concealing the missing record and breaking user intent. **Recommendation/owner:** content/mobile engineer reserve any deliberate default only for an explicit no-ID discovery state; return NotFound for a supplied missing ID. **Close:** request valid, deleted, random and absent IDs; assert exact requested content or honest missing state and no unrelated browser launch.

### RD-04 — P2 — Feed loading/error states do not follow Supabase loading/error state

**Class:** confirmed source async-state defect, dormant feed. **Evidence:** `reads/ReadsFeedScreen.tsx:39–53` reads `getReadsFeed()` once synchronously and sets ready in that same call. `features/reads/feed.ts:3–6` returns repository cache. `supabaseRepository.ts:646,700–701` asynchronously hydrates articles, with no feed subscription; query errors retain the prior array and refresh still marks the cache hydrated at 740–741. **Trigger/consequence:** cold mount shows “No reviews yet” before content arrives and does not rerender when it arrives; network failures may look like an empty catalog. Retry repeats a cache read rather than awaiting article completion. **Recommendation/owner:** content/data engineer expose an awaited, bounded content read with refresh/error semantics and preserve known content on refresh failure. **Close:** delayed success must move loading→ready without remount; failed reads must expose Retry; genuine empty remains distinct. Root broad source tests do not cover this journey.

### RD-05 — P2 — Archive and atmosphere promises do not match their effects

**Class:** confirmed interaction mismatch and reasoned UX critique, dormant feed. **Evidence:** `reads/ReadsFeedScreen.tsx:161–168` “VIEW ARCHIVE” navigates to the last array item rather than an archive. “Explore by Atmosphere” renders only `View` cards at 255–282, no press/filter/navigation. **Trigger/consequence:** users tap what appears to be a browsing affordance and get an arbitrary article or no action. **Recommendation/owner:** editorial/product designer remove decorative categories until there is real classification and a working filter; rename an intentional single-story link accurately or implement an archive list. **Close:** each visible action must yield its named destination; noninteractive atmosphere information must not suggest exploration.

### RD-06 — P2 — Published read times are character counts of snippets

**Class:** confirmed metadata/design-contract defect, dormant feed. **Evidence:** `reads/ReadsFeedScreen.tsx:55–57` calls `title.length + excerpt.length` “words”, divides by 20, floors to at least three minutes. `docs/audit/PROFILE_READS_SPEC.md` requires actual word count/200 or honest fallback. Domain `BlogPost` contains no article word count. **Trigger/consequence:** identical-length summaries can label radically different full articles with the same misleading reading effort. **Recommendation/owner:** content engineer use publisher/ingestion metadata when available or a clearly chosen fallback; omit unavailable estimates rather than manufacturing precision. **Close:** known article word counts yield expected minutes; missing metadata follows a documented rule, including accessibility announcement.

### RD-07 — P3 — Editorial hierarchy is repetitive and disconnected from dish discovery

**Class:** reasoned UX critique, not a measured usability failure. **Evidence:** `reads/ReadsFeedScreen.tsx:117,161,243,288–290` repeats the same dataset across Latest Review Stories, Trending Palettes and Recent Dispatches; final section always reuses the first post. Architecture-derived labels “KIN FOLK/KINFOLK”, “BRUTALIST” and “Trending Palettes” are not explained in food-discovery terms. Source name is shown in the main list, but neither the feed nor `BlogPost` carries a publication date. **Consequence:** a small library feels longer without giving a diner better evidence of freshness or relevance. **Recommendation/owner:** editorial/product design keep one credible food-guide list, show source/date/area and a dish/venue action, expand categories only from actual content metadata. **Close:** approved design review + a diner task test for finding a relevant guide; retain publisher attribution and excerpt-only rights boundary.

### RD-08 — P2 — Failed or cancelled article handoff has no in-screen reopen action; external-source contract is unresolved

**Class:** confirmed recovery omission plus integration gap, article route latent. **Evidence:** `reads/BlogPostWebViewScreen.tsx:20–26` automatically opens only on post change; render offers no Open Article/Retry button. `lib/security/safeLinking.ts:8,49–58` allows only `usehungry.com` and `www.usehungry.com`, swallows error into an alert and returns no failure status. `supabase/migrations/0009_blog_sources.sql:21–22` knows Eatbook/SethLui source homepages, while the product spec describes external blog aggregation. **Trigger/consequence:** deny/fail browser opening or return from it and the preview cannot reopen the original without remounting. A future genuine external publisher URL is rejected even when its content is deliberately ingested; no current blocked live publisher article was proven. **Recommendation/owner:** content/mobile/security engineer keep HTTPS and explicit provenance validation; show source/destination and user-controlled open/retry, propagate failure state, and approve publisher targets before adding them. Do not solve this by allowing arbitrary URLs. **Close:** allowed target opens/reopens, refused schemes/unknown hosts remain blocked, failed open offers retry and accessible feedback; live redirects and publisher rights need separate verification.

### RD-09 — P2 — Developer feature switches and “Slow 3G” do not simulate the stated feature/network behavior

**Class:** confirmed tooling behavior defect; development only. **Evidence:** `dev/DeveloperLauncherScreen.tsx:404–405` stores flags locally; all uses are rendering the switches at 744–765. No provider/feature gate consumes them. Network handler at 986–991 only changes local badge state and `useUIStore.isOffline`, optionally navigating Offline; no latency, transport failure, connection blocking or throttling is configured. **Consequence:** QA can believe floorplans are disabled or slow/offline requests were tested when only the panel changed. **Recommendation/owner:** QA/tooling engineer either wire deterministic injected conditions consumed by services, or rename controls “UI preview” and use real transport throttling separately. **Close:** demonstrate changed feature reachability and observable request delay/failure, including return to baseline; document what offline simulation does and does not prove.

### RD-10 — P2 — “Guest Dish” inspection silently authenticates the test session

**Class:** confirmed tooling-state defect; development only. **Evidence:** `dev/DeveloperLauncherScreen.tsx:583–595` calls `completeAuth()` and `completeOnboarding(false)` before opening a dish when `!isAuthenticated`. The public stall shortcut at 578–580 does not do this. **Trigger/consequence:** a signed-out reviewer opens Dish and then sees protected actions in an authenticated mock state; a smoke using that shortcut cannot prove guest detail/auth-gate behavior. **Recommendation/owner:** QA/navigation engineer preserve session state for public detail shortcuts and add explicit, clearly named authenticated presets. **Close:** inspect guest dish, confirm session stays signed out, then exercise protected save/review routing. This finding qualifies guest evidence, not a production auth bypass.

### RD-11 — P2 — Async presets are neither exclusive nor failure-recoverable, and debug counts can be stale

**Class:** confirmed missing tooling safeguards; race impact requires runtime reproduction. **Evidence:** named/auth preset handlers at `dev/DeveloperLauncherScreen.tsx:431–483` fire `.then()` without `.catch()`, busy guard or operation token; user can start another mode/reset while the first promise is pending. `enterUserMode` at 519–522 trusts an existing local UUID without rereading SDK session. Data inspector memo at 266–276 never recalculates while mounted; its “Dishes” count is `listPopularNearby().length`, not a catalog total. **Consequence:** later preset completion can overwrite a newer chosen mode, failures can produce unhandled rejections, and a stale or partial count can look authoritative. **Recommendation/owner:** QA/tooling engineer serialize/cancel preset operations, report failures, verify current provider session, scope counts and add an explicit refresh. **Close:** delayed A then B/reset must leave only the latest choice; rejected sign-in gives recovery; counts identify cached/popular subset and update when data/provider changes. No server authorization bypass is asserted.

### RD-12 — P2 — Developer controls lack distinguishable assistive-tech labels

**Class:** confirmed source semantics gap; development only, rendered accessibility unverified. **Evidence:** feature `Switch` at `dev/DeveloperLauncherScreen.tsx:757` has no accessibilityLabel/labelledBy; its adjacent text is a sibling. Network `Pressable` at 984 lacks role and selected state. `VersionPair` at 250–260 uses repeated V1/V2 labels without the parent comparison subject in each button label. Shared DevButton minHeight is 32 at 217. **Consequence:** a screen-reader user cannot reliably distinguish which flag/version is being changed, and small controls may be hard to tap. **Recommendation/owner:** QA/accessibility engineer provide unique labels and roles/selected states, and verify target bounds rather than assuming shared Button fixes overrides. **Close:** VoiceOver/TalkBack announces “Post Composer, version 2” and each named feature/current state; font scaling and native hit areas validated.

### RD-13 — P3 — Gallery layout is a limited preview, and its Back label overpromises

**Class:** confirmed source/design-rule mismatch plus unverified visual concern; prototype only. **Evidence:** `dev/DesignGalleryScreen.tsx:56–57` nests a same-axis ScrollView inside default scrolling Screen; item grid at 125–135 uses raw spacing and 30%/100px-minimum widths, 64px illustration containers and no long-label/font-scaling handling. At 110 “Back to Launcher” invokes `goBack()`, which does not guarantee the previous route is Launcher. **Recommendation/owner:** design-tooling engineer use one scrolling owner, tokens and adaptive card widths, label Back honestly or navigate explicitly; keep brand preview and actual screen acceptance distinct. **Close:** small-width/large-type/dark-mode native checks and correct navigation from every registered entry. No production blocker or measured clipping is claimed.

## Honest comparison with current first-party documentation

| Product / first-party evidence | User outcome compared with Hungry | Keep / change and tradeoff |

| [Safari Reader](https://support.apple.com/en-gb/guide/iphone/iphdc30e3b86/ios) documents user-controlled Reader presentation on supported pages | Hungry correctly avoids republishing full articles; original-browser handoff can let the platform handle reading and publisher pages. Overall assessment: the useful differentiator is “read about this food, then see the place on Hungry.” The current dormant feed spends too much code and hierarchy on editorial decoration while its retrieval and async fundamentals remain incomplete. The development panel is useful for speed, but confidence would improve more from honest state simulation and reproducible presets than additional switches.
