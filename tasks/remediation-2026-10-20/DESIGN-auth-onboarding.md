# Auth and onboarding remediation states

Governing sources: `docs/audit/AUTH_SPEC.md`, `design/stitch/DESIGN.md`, existing onboarding food assets. Preserve the approved orange/navy direction, typography and tokens. These states supersede older OTP length and reset-confirmation examples.

- Forms scroll above the keyboard; labels and manager hints remain stable when password visibility changes. Primary actions expose pending state and reject duplicate operations synchronously. Errors preserve entered work. Unavailable production OAuth controls and their divider are absent.
- Verification accepts exactly eight numeric digits. Resend is a separate real request, locked while pending, with a wall-clock cooldown. Unconfirmed login offers verification with the entered email. Reset request confirmation truthfully describes an email request; completed password reset offers sign-in, with no fake resend/email-app action. A consumed recovery code remains in the active recovery session during retry.
- Onboarding has one nonsecret, account-scoped persisted draft across cuisine, taste, dietary, authentication and location. Choices restore their matching carousel position. Neutral is a deliberate answer. Optional cuisine selection may be empty. A profile retake stages edits until Finish; cancellation preserves the previous profile. Finish commits once.
- Result discovery distinguishes pending, failed/retry, and genuinely empty recommendations. Every selected dietary requirement is mandatory and unknown metadata fails a requirement. A zero-match result never substitutes unrestricted dishes. Cards retain the actual dish photo, venue and price; no generic dish substitution. Save while guest retains the selected dish intent for idempotent execution after authentication.
- Location offers equivalent manual entry. Pending operations disable conflicting submission and reject stale completion. Back describes the actual navigation. Verification resumes at the outstanding location step; onboarding is complete only after that step.
- Reduced motion removes travel/stagger/loop effects; all content remains visible. Controls have at least 44-point targets and selected/busy labels. Large text and keyboard/native screen-reader acceptance requires candidate-device evidence and is not implied by source review.

Quiz Finish confirmation: authenticated users remain on the dietary step with a pending primary action while all staged preference fields save in one profile request. Native back and conflicting step actions are disabled during this request. Failure preserves the uncommitted draft and previous profile, displays a retry message, and re-enables Finish. Only a confirmed response from the current account generation may update the profile, mark the draft committed, clear skipped status and show the result/success. Guest Finish merges the same staged fields into the local profile once. Cancelling an untouched retake performs no profile write.

Quiz restoration: restoring a saved carousel offset, relayout, and step animation only change visual position; they never create an answer. Only an explicit card selection or a drag begun on the current taste question may persist a choice. Late momentum from a previous question cannot overwrite the restored answer.
