## Verification Budget

Use the smallest check that matches the change risk.

1. Small iterative changes: no full QA/QC, no `npm run ios`, no full suite, and no default `npm run typecheck`; run a focused check only when directly relevant.
2. Medium bounded changes: run focused tests/contracts; add `npm run typecheck` only for TS contract/import/prop changes.
3. Broad/risky/release changes: run `npm run typecheck`, relevant tests, `NPM_CONFIG_CACHE=/tmp/hungry-npm-cache npx expo-doctor` when dependency/native health is relevant, and simulator smoke when runtime risk warrants it.
